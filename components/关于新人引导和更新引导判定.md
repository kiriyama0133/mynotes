在成熟的产品中，将 Tour 分为 **“新人引导（Onboarding Tour）”** 和 **“更新引导（What's New / Feature Update Tour）”** 是行业标准做法。这两种 Tour 的**触发时机、视觉样式、持久化策略**都有显著区别。

我们使用的是Ark UI，所以估计演示也是围绕着这个tour组件来演示的。

### 两种 Tour 的核心差异

| 维度        | 新人 Tour (Onboarding)  | 更新 Tour (What's New) |
| --------- | --------------------- | -------------------- |
| **目标受众**  | 刚注册、或首次进入核心页面的用户      | 老用户（系统上线了新功能）        |
| **触发时机**  | 登录后 / 首次进入模型市场        | 登录后检测到有新版本功能         |
| **优先级**   | **最高**（没看完新人引导，绝不弹更新） | 次高（新人引导完成后才检查）       |
| **UI 表现** | 强制全屏遮罩、聚光灯、详细的“下一步”   | 轻量气泡、可以随时关闭、不强制阻断    |
| **生命周期**  | 一次性（看完/跳过即不再出现）       | 版本级（每次大版本更新弹一次）      |

## 架构设计

我们一般不会写两个单独的Tour，而是封装一个叫做useTourManager来统一管理状态、优先级和持久化，状态存储的策略是布尔值 `isOnboardingCompleted`（是否完成/跳过了新人引导）。版本号 `lastSeenVersion`（用户上次看过的版本号，比如 `v1.2.0`）。

因为肯定不能同时显示两个tour，加载时的判定顺序应为：

1. 检查是不是新用户？是 -> **触发新人 Tour**，结束。
    
2. 如果不是新用户，检查是否有新版本？是 -> **触发更新 Tour**。

比如下面的统一的管理：

```ts
// app/composables/useTourManager.ts
export const useTourManager = () => {
  const isOnboardingOpen = ref(false)
  const isUpdateOpen = ref(false)

  // 当前系统的最新版本号
  const CURRENT_APP_VERSION = 'v1.2.0'

  // 检查并决定展示哪个 Tour
  const checkAndTriggerTours = async () => {
    const user = useUser() // 你的登录状态
    
    // 1. 访客或新用户逻辑
    if (!user.isLoggedIn || user.isNewUser) {
      const localOnboarding = localStorage.getItem('gencos_onboarding_done')
      if (!localOnboarding) {
        isOnboardingOpen.value = true
        return // 优先级最高，直接返回
      }
    }

    // 2. 老用户检查更新逻辑
    const lastSeenVersion = localStorage.getItem('gencos_last_seen_version')
    
    // 如果本地没记录，或者系统的版本号大于本地记录
    if (!lastSeenVersion || lastSeenVersion !== CURRENT_APP_VERSION) {
      // 可以在这里加个后端请求，判断这次更新是否包含针对该用户角色的功能
      isUpdateOpen.value = true
    }
  }

  // 完成/跳过新人引导
  const finishOnboarding = () => {
    isOnboardingOpen.value = false
    localStorage.setItem('gencos_onboarding_done', 'true')
    // 新人引导结束后，立刻检查是否有更新（防止同一天加入又刚好遇到更新）
    checkAndTriggerTours() 
  }

  // 完成/关闭更新引导
  const finishUpdate = () => {
    isUpdateOpen.value = false
    localStorage.setItem('gencos_last_seen_version', CURRENT_APP_VERSION)
  }

  return {
    isOnboardingOpen,
    isUpdateOpen,
    checkAndTriggerTours,
    finishOnboarding,
    finishUpdate
  }
}
```

建议把这个逻辑放在 `app.vue` 或 `layouts/default.vue` 中，确保全局生效。

**更新 Tour 一定要轻量**：老用户对产品已经很熟悉了，如果更新一个新按钮，还要给他看一个全屏的遮罩，用户会非常反感。更新 Tour 尽量只针对**唯一变更的组件**进行 Spotlight 高亮，文案一句话带过。

**版本号的管理**：不要每次发版（改个错别字）都更新 `CURRENT_APP_VERSION`。只有在**新增了核心功能**（比如新增了“企业团队管理”、新增了“聊天发 3D 模型”）时，才更新这个版本号触发 Tour。

**后端兜底（跨设备）**：如果你只把状态存在 `localStorage`，用户在公司电脑看过了更新引导，回家用自己电脑登录，又会弹一次。对于登录用户，最好将 `isOnboardingCompleted` 和 `lastSeenVersion` 同步到后端的 `user_profile` 表中。

**后台配置化：如果你们运营很强，可以把这两个 Tour 的数据（步骤、文案、目标元素 ID）做成后台可配置的 JSON。前端只负责拉取 JSON，然后传给 Ark UI 渲染，这样改文案就不用发版了。

## arikui的组成

Ark UI 的 `Tour` 采用了声明式的组合式 API，将不同职责的部件拆分，让你能像搭积木一样构建引导流程。其核心结构如下：[](https://ark-ui.com/docs/components/tour.mdx)

- **`useTour` Hook**：这是状态与逻辑的控制器。它不负责渲染，而是管理所有引导步骤（`steps`）、当前激活的步骤索引、打开/关闭状态等，并提供 `start`、`next`、`prev` 等方法。[](https://ark-ui.com/docs/components/tour.mdx)
    
- **`Tour.Root`**：根容器，接收 `useTour` 返回的控制器实例（`tour` prop），并将状态传递给所有子部件。[](https://ark-ui.com/docs/components/tour.mdx)
    
- **`Tour.Backdrop`**：全屏遮罩层，负责视觉上“压暗”背景，并阻止用户与页面其他部分交互。[](https://ark-ui.com/docs/components/tour.mdx)
    
- **`Tour.Spotlight`**：聚光灯层，它的核心作用是“挖空”遮罩，让当前步骤的目标元素清晰可见。[](https://ark-ui.com/docs/components/tour.mdx)
    
- **`Tour.Positioner` & `Tour.Content`**：负责引导卡片（如提示框）的定位和渲染，内容可完全自定义。

每个 `tooltip` 类型的步骤都定义了一个 `target` 函数，该函数返回一个 DOM 元素（如 `document.querySelector('#btn-upload')`）。`Tour.Positioner` 会使用定位算法（如 Floating UI）计算出目标元素的位置，并将 `Tour.Content`（引导卡片）精准地放置在目标附近（如 `top-start`）。`Tour.Spotlight` 和 `Tour.Backdrop` 协同工作，实现高亮效果。`Spotlight` 通常通过 CSS 的 `box-shadow` 或 `clip-path` 在遮罩层上“挖”出一个透明区域，使得只有目标元素被高亮显示，而页面其他部分被遮罩覆盖。同时，它还会阻止事件穿透，确保用户只能与高亮区域交互。

`Tour` 的遮罩和动画控制非常灵活。

- **遮罩控制**：你可以通过 `mask` 属性决定是否启用遮罩，或自定义其样式和颜色。
    
- **过渡动画**：`Backdrop` 和 `Spotlight` 等部件都支持通过 CSS 类来添加过渡效果（如 `transition: opacity 0.3s`），从而实现平滑的显示和隐藏动画。

`Tour` 在引导过程中非常注重可访问性。

- **焦点陷阱 ：引导激活时，键盘焦点会被限制在当前步骤的引导卡片内，用户无法通过 `Tab` 键将焦点移到背景页面上，这确保了操作的连贯性。[](https://blog.gitcode.com/0f7e0ef231e0de5057a09ee9f028f35e.html)
    
- **键盘导航**：支持通过方向键在步骤间切换，并可使用 `Escape` 键关闭引导，提升了无障碍体验。、
