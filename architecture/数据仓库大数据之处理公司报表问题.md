在不同pg的实例中，表机构遵循三范式保证高并发事务的写入性能，一旦业务方需要跨越多个限界上下文拉取年度经营报表，直接跨服务调用api聚合和跨库JOIN又慢又拖垮线上库，因此我们会使用到数据仓库，通过ETL/ELT把分散的业务数据抽离出来，重组为面向分析查询的分层模型与列式存储。

我们接下来需要建立完整的数仓的知识体系，需要放下DDD的聚合根和三范式拆分习惯，学习一下kimball维度建模的核心范式，把表严格划分为 事实表 来记录业务过程与可累加度量，比如支付流水、出库数量 。和维度表，记录分析视角上下文，如时间、门店、客户标签，理解 **星型模型** 如何通过适度反范式冗余实现空间换时间。

同时摸清企业数仓的标准四层架构流向，我们通过ODS原样同步业务表 -> DWD明细数据层，清洗脏数据并退化维度->DWS汇总数据层，按主题轻度预聚合->ADS应用数据层，直接对接报表接口。并重点掌握记录状态变迁的缓慢变化维。

之后打通数据管道，从传统批处理ETL转向CDC + ELT，传统凌晨跑定时脚本扫线上表做 ETL 的方式已逐渐被现代云原生数仓淘汰，如今企业主流架构是 **CDC（变更数据捕获） + ELT（先入仓、后利用数仓算力转换）**。

- **抽取与同步（E + L）**：直接基于你熟悉的 **PostgreSQL** 开启逻辑复制（`wal_level = logical`），学习使用 **Apache SeaTunnel**（配置极简的云原生同步工具）或 **Debezium / Flink CDC** 实时解析 WAL 日志，对线上微服务零侵入地把增删改流式同步进数仓 ODS 层。
    
- **仓内建模转换（T）**：重点上手 **dbt（data build tool）**。它把混乱的数仓存储过程和 SQL 脚本彻底软件工程化——支持 `SELECT` 模块化引用、自动推导表级血缘图谱（Lineage）、数据质量断言测试（非空、唯一性校验）以及 Git CI/CD 集成，对有 Clean Architecture 分层意识的后端开发者非常亲切。

紧接着要学习OLAP列式引擎的底层机制，目前工业界企业报表与实时数仓最主流的开源底座是**Apache Doris / StarRocks** 这个新一代MPP列式数仓，完全兼容mysql协议，支持高并发多表星图JOIN，又原生支持主键实时Upsert，最契合公司常规业务的报表。这一步最重要的是这几个概念：
1. 列式存储与编码压缩
2. 分区分桶与稀疏前缀索引
3. SIMD向量化执行
4. 异步物化视图

最后我们要学习串联存算分离存储、网关治理与 BI 报表出口，现代云原生数仓普遍演进到了存算分离（Shared-Data）架构：计算节点无状态、按需弹性扩缩容，底层数据直接以列式格式落在兼容 S3 协议的对象存储上——这正好可以复用你熟悉的 **MinIO** 作为冷热分层或存算分离后端（进阶还可了解 **Apache Iceberg** 湖仓一体表格式）。
