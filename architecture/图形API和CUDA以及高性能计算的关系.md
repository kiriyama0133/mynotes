鉴于之前学习过opengl的相关知识，我也有一些个人思考，我想稍微谈谈图形api和cuda编程两者的模型和思路到底有什么不同，它们都是在gpu上进行运算。

图形api确实可以让我们理解gpu如何组织任务、调度工作、访问显存以及执行并行程序，但是不能直接让我们掌握gpu的全部硬件架构，尤其是nvidia gpu的sm、warp、tensor core、寄存器分配细节，我们还需要配合cuda、ptx 和 gpu架构资料来统一学习。

现代图形api包括了vulkan、d3d、metal，如果我们是系统学习了的，应该会对gpu的任务提交和异步执行，理解gpu流水线，访问资源和数据布局有着基本的认识。

但是在没有cuda的基础上，很多知识都不能理解。我们可以去学习一下compute shader技术，它已经不只是传统图形渲染技术，而是 GPU 通用计算的一种编程模型。你可以让gpu并行执行对数百万个体素计算esdf，对点云过滤，对大量碰撞球距离检测，对体素占据数据进行更新、对大量粒子进行物理模拟，这些工作与 CUDA 中的并行计算有很强的相似性，但是由于本人是真的没有学习过cuda，所以说不出大概，说不出一二。

在正式学习cuda和ptx等相关知识，我们需要建立gpu的硬件执行模型，如果我们是一个传统图形学开发者，应该只是接触了gpu获取顶点数据，gpu存储和采样图像数据，gpu执行顶点和片元计算，cpu向gpu提交绘制任务，gpu进行深度比较，gpu组织和绘制。但这些知识主要描述的是**GPU 对外提供的功能和编程接口**，并没有回答 GPU 内部是如何完成这些工作的，接下来的笔记是我参考网上资料和ai给我的回复编写的：

说到gpu，cuda实在是太出名了，所以我们一般以nvidia gpu为例，把gpu理解为一个由多个SM组成的并行的计算设备。一个简化的结构是：

![](https://pub-dd8e151a60af44cfbe36beaaf0ad54e8.r2.dev/2026/11/1795507971903-b8nun2uq.webp)

SM最值得关注，因为GPU的大量计算工作，都是在SM内部完成，SM的内部有几个重要组件：

CUDA Cores 来执行大量普通函数、浮点运算；warp scheduler调度warp来执行指令；register file 保存线程使用的寄存器； shaderd memory 供同一线程块内线程共享数据；load/store units 执行内存读写；special function units 执行部分特殊数学运算；tensor cores加速矩阵乘加等特定运算。

>**GPU 并不是简单地拥有很多 CPU 核心，然后同时执行很多任务。它有一套专门针对大规模数据并行设计的执行架构。**

CPU 更倾向于让少量核心快速执行复杂的控制逻辑，而 GPU 更倾向于让大量线程执行相似的指令。因此gpu天生适合图像处理、点云计算、矩阵运算、体素邻域计算、神经网络。

对于后续的学习，我建议先从理论入手，看gpu架构，执行模型和内存体系再到并行计算。我们会先用普通 C++ 建立 CPU 端的对照实验，再使用 CUDA C++ 让程序运行在 GPU 上。
