curobo在传统运动规划任务上表现的非常出色，他可以把原本在cpu上串行执行的复杂任务搬运到gpu上进行大规模的并行处理。因此，它不仅仅是一个运动学解算或是路径规划库可以解释的。

根据查找的资料来看，它能够提供高精度的正/逆运动学 FK/IK求解，精度可以达到亚毫米级别。因此可以非常精确地计算出机械臂关节需要转动多少度数。碰撞检测中，使用碰撞球模型来近似机械臂，并在gpu上并行检查机械臂与自身、场景之间是否存在碰撞，速度极快。说到路径规划和轨迹优化这就是它的强项，因为cuRobo不采用传统的随机采样如RRT，而是将运动生成视为一个全局优化问题，它会在GPU上并行评估成千上万个候选轨迹，并直接优化出一条在时间、平滑度、避障等方面都最优的轨迹，官方的数据显示，他可以在jetson orin上100ms左右为ru10机械臂完成规划。

传统rrt中，我们假设有一个6自由度机械臂可以表示为q1~q6。这六个关节角度构成了一个六维空间，我们叫做构型空间：

![](https://pub-dd8e151a60af44cfbe36beaaf0ad54e8.r2.dev/2026/11/1794899318459-9d9f7hgg.webp)

这个空间里，每一个点代表机械臂的一组关节角度，一部分点对应机械臂与障碍物发生碰撞，另一部分是合法的无碰撞状态。我们需要找到一条从起点到终点的合法路径。

传统rrt思路是随机探索空间，从起点创建一课树，然后再构型空间中随机采样一个点qrand，找到树中距离采样点最近的节点qnear，从qnear朝qrand延伸一小段，得到qnew，检查新节点以及连接边是否与障碍物碰撞，如果合法，就把新节点加入到树，重复以上的过程直到找到目标附近的节点。

rrt找到的是一条可行路径，而不是一条适合机器人直接执行的轨迹，这个是理解curobo的关键。但是rrt找到的路径不一定适合机器人执行，因为一条合法路径就满足，但是对于机器人来说，我们要考虑关节速度限制、关节加速度限制、动力学约束等等因素。

所以传统机器人的规划经常采用RRT找到无碰撞路径，路径平滑算法负责改善路径质量，时间参数化算法负责生成可以执行的速度曲线。这套方案没有问题，而且在很多场景下非常有效。

但它存在一个缺点：路径规划和轨迹优化是分离的，RRT 并不知道后续的轨迹优化器希望得到什么样的路径。

因此curobo选择了另一条速录，我们不把问题看做简单的找一条路径，而是把整个运动过程看做优化问题，假设我们将机械臂的轨迹离散成T个时间点：

$[ Q = \begin{bmatrix} q_0\\ q_1\\ q_2\\ \vdots\\ q_T \end{bmatrix}$ 

其中每一个 $q_t$ 都是一个六维关节状态。那么整个规划问题就可以表示成：$\boxed{ Q^*=\arg\min_Q J(Q) }$ 
这里的 $J(Q)$ 是一个综合代价函数它可以包含多个部分：
 $J(Q)= w_cJ_{collision} +w_vJ_{velocity} +w_aJ_{acceleration} +w_jJ_{jerk} +w_gJ_{goal}$ 

各部分分别表示：

| Cost               | 作用            |
| ------------------ | ------------- |
| $J_{collision}$    | 惩罚与障碍物发生碰撞的轨迹 |
| $J_{velocity}$     | 惩罚过大的关节速度     |
| $J_{acceleration}$ | 惩罚过大的加速度      |
| $J_{jerk}$         | 惩罚运动方向变化过于剧烈  |
| $J_{goal}$         | 确保机械臂到达目标     |

>代价函数是一个打分的方案，本质上是一个数学函数，接受一个输入，得到一个输出，输出越接近0越好。他可以运用到机器人运动学规划里，我们不只是输入一个数字而是一组关节角度，那么代价函数就可以对这组关节角度进行评价，如果机械臂和障碍物碰撞，那么碰撞代价就会变大，如果比较理想，碰撞代价就比较小。而curobo里的的代价函数有很多项，把整体作为优化的目标。


这意味着，规划器不再只是寻找一条可行路径，而是在寻找一条综合代价尽可能低的轨迹。

![](https://pub-dd8e151a60af44cfbe36beaaf0ad54e8.r2.dev/2026/11/1794900076435-pzsc576z.webp)

当然有一个需要注意的细节，优化问题通常是非凸的，不能保证从任意初始化轨迹出发，都能找到全局最优解。这也是curobo接下来的一个重要设计出现的原因。

这里插个凸优化知识，如果一个函数满足了一下这个条件，就叫做凸函数：

 $f(\lambda x+(1-\lambda)y) \leq \lambda f(x)+(1-\lambda)f(y)$  其中：$0\leq\lambda\leq1$ 。**在函数图像上任意取两个点，用直线连接它们，那么这条直线不会低于函数图像。** 例如：$f(x)=x^2$ 

![](https://pub-dd8e151a60af44cfbe36beaaf0ad54e8.r2.dev/2026/11/1794900808347-i4pjo7p1.webp)


这就是个典型的凸函数，有一个非常重要的性质，只要找到了局部最小值，就一定找到了全局最小值，因为凸优化容易处理。因此，对于满足适当条件的凸优化问题，我们有比较强的理论保证。当然，实际计算仍然需要考虑步长、数值精度和收敛条件。

如果没有上面的保证，可能存在多个局部最小值，多个局部最大值、鞍点、复杂的函数曲面，如：

$\boxed{f(x)=(x^2-1)^2}$  这个函数的图像看起来像两个碗连在一起。假如梯度下降从 \(x=0.8\) 开始，它会向右边的低谷移动。如果从 \(x=-0.8\) 开始，它会向左边的低谷移动。两者都能找到全局最优值，但会找到不同的最优解，这个叫做多解问题。说明：**无碰撞路径构成的可行空间，并不一定是凸集**

正向运动学本来就是包含非线性的，当你改变关节角度时，机械臂末端的位置并不会按照简单的线性关系变化，而碰撞检测又依赖机械臂每个连杆的实际空间位置，整个计算链条中存在大量非线性关系。这就使得碰撞代价很难保持凸性。

所以curobo针对非凸优化使用的是先探索，再精细优化的策略，cuRobo 当前版本的优化框架提供了不同类型的优化器：

|优化器|思路|
|---|---|
|MPPI|采样大量候选轨迹，根据代价调整采样分布|
|Evolution Strategies|根据候选解的代价统计更新搜索分布|
|L-BFGS|利用梯度和历史信息进行局部优化|
这种很适合gpu，因为gpu可以同时处理大量候选轨迹。

nvidia特别强调gpu并行优化，因为传统数值优化通常需要从一个初始解开始，不断迭代。如果初始轨迹不好，就可能：

- 陷入局部最优。
    
- 找不到可行轨迹。
    
- 无法绕过复杂障碍物。
    
- 需要大量迭代才能收敛。

cuRobo 的关键创新之一，就是不只优化一条初始轨迹，而是同时优化大量不同的初始轨迹。假设有100条不同的初始轨迹，我们就可以同时计算正向运动学、碰撞距离、代价函数、梯度、优化更新，最终从这些候选轨迹中选择质量较好的结果，这个很适合gpu，因为我们可以让大量相似的计算任务同时执行，curobo里的优化过程就是这样干的。NVIDIA 在 2023 年发布的 cuRobo 研究中，使用了 L-BFGS、并行 noisy line search 和 particle-based optimization 等技术。其研究报告展示了多初始轨迹并行优化的性能优势。

但是基于采样的规划期不是完全抛弃了，它可以帮助优化器找到一个比较合理的拓扑路径，所以curobo实际上采用的是混合思路：

## 核心库

截止2026年11月，curobo v2已经是一次较大的架构重写，官方将pytorch、cuda和wrap列为了核心技术基础。

![](https://pub-dd8e151a60af44cfbe36beaaf0ad54e8.r2.dev/2026/11/1794901400798-fgzv1qje.webp)

### wrap

wrap就是wrap-long，是nvidia开发的gpu并行计算框架，可以让开发者用接近python的语法编写gpu kernel，而不必直接编写大量的cuda c++，比如说：

```python
import warp as wp

@wp.kernel
def add_kernel(
    a: wp.array(dtype=float),
    b: wp.array(dtype=float),
    out: wp.array(dtype=float)
):
    i = wp.tid()
    out[i] = a[i] + b[i]
```

这里我们做了： $out_i=a_i+b_i$  ，但是和普通版本的区别在于`@wp.kernel`可以声明一个gpu kernel，`wp.tid()`可以获取当前线程的索引，每个gpu线程可以负责处理一个数组元素，wrap负责将python风格的kernel编译成gpu可以运行的代码。

### curobolib

这是curobo自己实现的一组底层计算模块，而不是独立的nvidia通用计算框架，他可以使用cuda实现机器人算法kernel，使用c++包装kernel，编译后通过Pytorch接口供python调用。

这样就可以把机器人计算从python层下沉到cuda kernel。不过有一个版本区别必须说明：cuRobo V2 在 2026 年的重构中，重新组织了内部模块。不能把 V1 的 `curobolib` 目录结构直接当作 V2 的整体架构。

### TrajOpt

根据上面的图示，这个和之前的wrap、curolib不是一个层间，他不是gpu编程框架也不是底层计算库，而是一个给机器人运动规划中的数学优化问题以及其求解器。在 cuRobo V2 中，轨迹优化可以使用不同的优化器，例如：

| 优化器                  | 主要作用         |
| -------------------- | ------------ |
| MPPI                 | 基于采样的轨迹搜索    |
| Evolution Strategies | 基于种群的优化搜索    |
| Gradient Descent     | 基于梯度的优化      |
| L-BFGS               | 利用梯度历史信息进行优化 |
| Conjugate Gradient   | 共轭梯度优化       |

### PTX

这个是最为底层的，它不是库，而是一种 GPU 虚拟指令集（Virtual ISA）。如果你熟悉 x86 汇编，可以把它理解为 NVIDIA GPU 生态中的一种中间汇编表示：

```ptx
.visible .entry add_kernel(
    .param .u64 a,
    .param .u64 b,
    .param .u64 out
)
{
    // GPU 指令
    ret;
}
```

这里仅展示 PTX 的基本形式，不是完整的加法 Kernel。开发者通过cuda c++或者wrap kernel编写的代码会被ptx的gpu虚拟指令表示，然后会转换为sass面向具体的gpu架构的机器执行，最后再交给nvidia gpu执行，这个就是经典的cuda编译路径。因为如果所有 CUDA 程序都必须直接针对每一代 GPU 编写汇编，那么开发和维护成本会非常高。

## 选取工作空间给curobo处理

curobo支持voxel grid 如esdf作为环境碰撞模型，这个对于我们检测防撞来说很重要，但这里有一个关键区别：

> cuRobo 所说的 Voxel Grid，并不只是一个记录 Occupied / Free 的立方体网格，而是可以在每个体素中存储 ESDF 距离值的三维网格。

这个正好适合轨迹优化中的碰撞距离计算，curobo实际需要的数据为例，他提供了`WorldVoxelCollision`，可以使用 ESDF Voxel Grid 进行碰撞检测。

一个体素网格可以抽象为：X方向的体素、Y方向的体素、Z方向的体素、voxel size，**每个体素存储一个距离值**

cuRobo 可以查询机械臂碰撞球与这些体素距离场之间的距离。例如：

 $d_{\text{collision}} = ESDF(p_{\text{sphere}})$ 

这里的 $p_{\text{sphere}}$是机械臂某个碰撞球的位置，规划器就可以利用这个距离信息判断是否碰撞，以及离障碍物还有多远，所以之后我们用于给curobo处理的工作空间都是推荐使用体素模型来处理。

我们可以根据目标点来选取一个工作空间，然后对工作空间点云进行滤波，滤波了之后再去映射到固定分辨率的三维网格，之后我们要考虑枝叶厚度、定位误差和安全距离，因此需要使用esdf generation来计算每个体素到最近障碍物的距离，之后交给curobo voxel collision进行碰撞检测和轨迹优化。

注意：膨胀和 ESDF 生成的先后顺序可以根据你的安全距离定义调整。也可以直接在 ESDF 上通过安全距离阈值实现碰撞裕量，不一定要先物理膨胀体素。官方目前的实现中，V2 可以直接通过自身 Mapper 生成 ESDF，也可以使用 nvblox 等外部地图来源提供的 ESDF。官方还特别提到，轨迹优化阶段直接查询稠密 ESDF Grid，比直接查询 nvblox Mapping Layer 更快。

### tsdf 与 esdf

tsdf叫做 截断有符号距离场，主要用于从深度相机或激光观测中融合、重建三维环境。esdf是欧几里得有符号距离场，主要用于查询空间中任意位置距离最近障碍物有多远。

>TSDF 更关注如何从传感器观测构建环境；ESDF 更关注机器人距离障碍物还有多远。

这两个要理解就需要先理解sdf，中文叫做有符号距离场：

![](https://pub-dd8e151a60af44cfbe36beaaf0ad54e8.r2.dev/2026/11/1794904577940-h6g3wzjt.webp)

我们希望对空间中的每一个位置 p，都能回答一个问题：这个位置距离障碍物表面有多远，所以需要定义个函数： $D(p)=\pm \operatorname{dist}(p,\partial O)$ ，p是控件中的一个位置，O是障碍物占据的区域，$\partial O$ 是障碍物表面，dist是到障碍物表面的最短距离。

我们约定：

|位置|距离值|含义|
|---|---|---|
|障碍物外部|正数|距离障碍物还有多远|
|障碍物表面|0|正好位于障碍物边界|
|障碍物内部|负数|已经进入障碍物内部|
这种表示方式有一个非常大的优点，他可以告诉我们是否发生了碰撞，还可以告诉我们距离碰撞还有多远，这对于轨迹优化非常重要。

tsdf叫做截断有符号距离场，核心思想是：**根据传感器观测到的表面，计算附近体素到表面的有符号距离，并将距离限制在一个指定范围内。** 

![](https://pub-dd8e151a60af44cfbe36beaaf0ad54e8.r2.dev/2026/11/1794904945145-g2r4utag.webp)

假设我们设置截断距离： $\mu=0.05m$ ， 也就是 5 cm。那么距离表面超过 5 cm 的区域，其 TSDF 值就会被截断。通常可以把计算写成：
$$
D_{\text{TSDF}}(v)= \operatorname{clamp} \left( \frac{z_{\text{measured}}-z_v}{\mu}, -1,1 \right) 。
$$

Zmeasured是深度相机实际测得的表面深度，Zv是体素中心投影到相机坐标系后的深度，$\mu$ 是截断距离。

因为你用深度相机或者双目相机每次观测都可以提供一张深度图，例如说某一帧观测到了树枝表面，相机可以知道树枝表面距离自己多远，可以把这次观测投影到三维体素空间，更新表面附近的tsdf值，下一帧从另一个角度观测到同一根树枝时，又可以更新这些体素。TSDF 通常采用加权平均的方式融合多次观测：
$$
D_{\text{new}}= \frac{ W_{\text{old}}D_{\text{old}}+ wD_{\text{obs}} }{ W_{\text{old}}+w }
$$
其中：

- $D_{\text{old}}$：之前融合的距离值。
- $D_{\text{obs}}$：当前帧的距离观测。
- $W_{\text{old}}$：之前累计的权重。
- $w$：当前观测的权重。

这样就能减少单帧深度噪声的影响。

因此，TSDF 特别适合：

- 多帧深度融合。
    
- 降低传感器噪声。
    
- 重建连续表面。
    
- 生成三维网格模型。

esdf叫做**欧几里得有符号距离场**，ESDF 的全称是：**Euclidean Signed Distance Field** ，它可以计算空间中每个位置到最近障碍物表面的真实欧几里得距离。对于任意一个空间位置 \(p\)，ESDF 都尝试计算：

$$
 D_{\text{ESDF}}(p)= \pm\min_{q\in\partial O} \|p-q\|_2 
$$

这里的：

$$
 \|p-q\|_2= \sqrt{ (x_p-x_q)^2+ (y_p-y_q)^2+ (z_p-z_q)^2 } 
$$

就是我们熟悉的三维欧几里得距离，与 TSDF 不同，ESDF 不关心某个相机是从哪个方向观察到障碍物的。假设机械臂的一个碰撞球半径为： r=0.04m ，也就是 4 cm。某个时刻，这个碰撞球的中心到障碍物表面的距离为： $D_{\text{ESDF}}(p)=0.06m$ ，那么理论上的表面间隙为：
$$
 d_{\text{clearance}}=0.06-0.04=0.02m 
$$
也就是机械臂距离碰撞还有 2 cm。如果：$D_{\text{ESDF}}(p)=0.03m$ ，则： $d_{\text{clearance}}=0.03-0.04=-0.01m$ ，意味着碰撞球已经与障碍物发生重叠。

esdf还有一个优点，叫做梯度，因为 ESDF 是一个距离函数，所以可以进一步计算它的梯度：

$$
 \nabla D(p)= \begin{bmatrix} \frac{\partial D}{\partial x}\\ \frac{\partial D}{\partial y}\\ \frac{\partial D}{\partial z} \end{bmatrix} 
$$

在距离场足够光滑的位置，梯度可以告诉我们距离增长最快的方向， 如果想远离障碍物，可以沿着距离增大的方向移动， 如果机械臂太靠近障碍物，可以利用距离梯度产生避障优化方向。

![](https://pub-dd8e151a60af44cfbe36beaaf0ad54e8.r2.dev/2026/11/1794906115260-dborqs6c.webp)

ESDF 在障碍物表面、等距离区域交界处等位置可能不可微或存在梯度不连续，因此实际优化器还需要处理这些情况。

## 实践

curobo在机器人项目里不是一个简单的fk/ik库，**而应该被定位为运动学计算、碰撞检测和运动生成的核心计算引擎。**

它也不是完整的机器人控制系统。它负责计算机器人应该怎样运动，而机器人驱动、实时状态反馈、轨迹执行、安全联锁等工作，应该由外围系统负责。

我问了ai和查阅了相关资料，nvidia的官方的文档和源码，有了一些基本的认知，以ai推荐给我的项目来说，他推荐一个采用ros2封装的curobo开源项目，调用了规划api，还把规划器、机器人控制、相机感知和ros接口拆分成了独立职责。

一个curobo在整个机器人系统里负责了机械臂当前位于的某个关节角度、相机检测到一个物体，上层任务系统给出抓取目标的位姿，机械臂需要绕过工作台、工件和其他障碍物，规划一条可以执行的关节轨迹，最终让机器人可以到达位置抓取，这个完全不是一个Ik就能完成的！

urdf负责描述了机械结构，但是curobo需要额外的碰撞球、自碰撞忽略矩阵等配置，一个机器人模型的解析有输入：

urdf/xacro、关节名称和关节类型、连杆之间的变换关系、关节限位、末端执行器坐标系、碰撞几何体，curobo根据机器人模型建立内部运动学和碰撞计算模型。

在curobo中，碰撞球通常是需要我们自己设计和配置和curobo负责读取这些碰撞球，并在运动规划里使用它们，他不会仅仅凭借urdf中的圆柱尺寸，就自动替我们生成一套合理的碰撞球，不过，cuRobo 提供了碰撞球生成、调整和可视化相关的工具，可以辅助我们完成这项工作。目前官方提供了`RobotBuilder`，可以从 URDF 构建机器人配置

### 密集型目标场景

对于密集型目标的抓取任务里，业界推荐建立工作空间的全局地图，再进行全局抓取顺序的规划，执行过程中，持续更新局部地图，**并根据实际情况重新规划。** 

但是不建议建立一张完全静态的全局地图，然后按照固定顺序执行所有抓取动作。更合理的是采用一种全局规划+滚动执行的方法。

只依赖当前的相机视角进行抓取，容易出现遮挡问题、抓取顺序问题、碰撞问题、可达性问题、抓取后的空间变化。因此只根据单帧RGB-D图像就决定的话，肯定是不够的，因此我们需要一个全局地图让系统同时考虑当前所有已观测到的物体的位置和形状，物体之间的空间关系、机械臂的可达空间、目标之间的遮挡关系、抓取某个物体之后可能释放出的空间。

因此我们建议把任务分为五层：全局环境的感知，让我们的高质量深度图生成点云，参与到多视角的融合里去。全局地图和物体建模，建立tsdf和esdf和目标实例。然后是全局抓取顺序的规划，通过可抓性、遮挡关系、碰撞风险、抓取收益来判断。局部抓取运动规划，依靠curobo或是其他的来实现。最后是执行和地图更新，我们需要抓取验证，场景变化检测，地图更新和重新规划。一直循环下去直到任务结束。

全局抓取顺序比较难确定，不建议简单按照物体距离、目标优先级或者检测置信度就这样简单地排序，应该建立一个抓取候选评分模型，假设识别到N个物体，就应该对每个物体生成若干份抓取的候选姿态，对每个候选抓取计算评分。然后还有个问题，抓取了一个物体之后能够给后续任务释放多少空间，如果只考虑当前抓取成功率，系统可能一直选择 A；但从全局任务效率看，优先处理 B 可能更好，我们可以定义一个空间释放收益，这个是初期、可实现可扩展的思路。


## 姿态管理

在平常的任务当中，我们不可能像仿真环境一样预先就有目标物体的模型，因此，获得最佳的抓取姿态就是一个很大的问题。我们不可能以一种固定的姿态去抓取，这样对curobo的路径规划还是抓取本身而言都是一种大的负担，我检查了一下curobo v0.7 warp 1.19上，提供了三种比较好的抓取姿态优化机制。

curobo原生并行姿态集合寻优GoalToolPose多姿态Goalset。cuRobo 原生的 `_goalset_pose_distance_template` 核函数支持把 K个候选抓取姿态（例如 K = 9 或 12个不同倾角与偏航角的法兰位姿）打包进同一个 GoalToolPose(num_goalset=K)张量。

cuRobo 的 GPU LM 优化器会在单次求解（约 35~50 ms，我的平台是nvidia jetson orin）内同时评估所有 K 个姿态，自动选出和esdf障碍物以及自身机械臂连杆零碰撞，距离当前关节角位移最小，手腕不需要大幅拧转、远离关节奇异点和限位最小的抓取姿态。

### 基于目标空间位置的径向扇形姿态生成

还有一种叫做基于目标空间位置的径向扇形姿态生成+curobo goalset择优。我们甚至都不需要使用点云的法向量，仅仅根据目标在机械臂的基座坐标系下的坐标和肩部/观测点相对方位，就能构造物理上最顺手的候选姿态集交给curobo，这个应该是适合大部分的场景的，这个值得大篇幅来说说看，这种算法广泛应用于机器人抓取多视角规划、游戏中的环绕镜头/技能释放、以及三维重建的相机视角采样：

假设目标点的空间坐标为 $\mathbf{P}_{target} = (x_t, y_t, z_t)$，我们需要在水平面（或指定基准平面）上生成 N个姿态，采样点到达目标点的距离是R，我们设扇形朝向的基准角度，例如目标的正前方或当前观察者与目标的连线方向为中心方向角$\theta _{center}$  ，扇形的总覆盖角度比如90或者pi/2弧度为张角delta theta。

高度偏移为H，俯仰角为![](data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAoAAAAYCAYAAADDLGwtAAAAJ0lEQVR4AezSsQkAAAwCwZD9h3YAQexs3trq+L9yHCMUPPCYwDAKAQAA//8NGmfoAAAABklEQVQDAGPwADF760BpAAAAAElFTkSuQmCC)𝜙，它们决定相机/执行器是平视、俯视还是仰视目标。之后我们计算采样点的位置，对于第i个采样点为(i = 0, 1 .... N-1)。

**计算当前角度 $\theta _{i}$**：

$$
\theta _{i}=\theta _{center}-\frac{\Delta \theta }{2}+i\cdot \frac{\Delta \theta }{N-1}\quad (N>1)
$$

**计算三维坐标$\mathbf{P}_{i}$以 \(Z\) 轴向上、\(XY\) 为水平面为例：


![](https://pub-dd8e151a60af44cfbe36beaaf0ad54e8.r2.dev/2026/11/1795248800063-lvq9s6gd.webp)

然后我们计算朝向目标的LookAt矩阵，也就是朝向目标的姿态，生成位置后，必须让执行器（如相机光轴或机械臂末端 \(Z\) 轴）对准 $\mathbf{P}_{target}$。

**前向向量 $(\mathbf{f}$, Forward)**：从采样点指向目标点并归一化：

$$
\mathbf{f}=\frac{\mathbf{P}_{target}-\mathbf{P}_{i}}{\|{}\mathbf{P}_{target}-\mathbf{P}_{i}\|{}}
$$

右向向量则是利用世界坐标系的上方向量0 0 1来进行叉乘：

$$
\mathbf{r}=\frac{\mathbf{f}\times \mathbf{u}_{world}}{\|{}\mathbf{f}\times \mathbf{u}_{world}\|{}}
$$

>(注：如果 f 几乎垂直于地面，需更换参考轴以避免万向节死锁)

上向向量用于重新正交化：
$$
\mathbf{u}=\mathbf{r}\times \mathbf{f}
$$
构建旋转矩阵，根据具体坐标系约定组合基向量，例如在常见的机器人/计算机视觉标准（+Z 轴朝前，+X 轴朝右，+Y 轴朝下）中：  
$$
{R}=\left[\begin{matrix}\mathbf{r}&-\mathbf{u}&\mathbf{f}\end{matrix}\right]
$$
最后将 $\mathbf{R}$ 转换为四元数 $(q_x, q_y, q_z, q_w)$ 即可。之后还要经过批量的评估和择优才能选出真正可行并且最优的抓取姿态，径向扇形生成的 N 个候选姿态组成一个 Batch（例如 `Pose` 张量，维度为 `[N, 3]` 和 `[N, 4]`），一次性送入 `IKSolver`，之后是curobo来接管了。

核心本质就是lookAt矩阵，因为扇形采样的几何要求就是“末端执行器必须对准目标点”。不过实际情况只是lookAt解决了指向问题，在此基础上，右乘局部旋转矩阵。


在实际情况下，goalset会由于最小关节位移的代价有限选择最接近当前的姿态的候选解，


最后一种是curobo的轴向自由度松弛PoseCostMetric旋转权重松弛，curobo的`PoseCostMetric(reach_vec_weight=[w_rx, w_ry, w_rz, w_x, w_y,w_z])` 支持将位置权重 `[w_x, w_y, w_z]` 锁紧为 1.0。同时降低绕工具轴向旋转 w_rz，或微倾角权重，让优化器在连续空间内自动微调手腕角度以避开障碍物。
