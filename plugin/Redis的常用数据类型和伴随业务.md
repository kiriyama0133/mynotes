## 数据类型

redis中有5种基础常用的数据类型，这里梳理了实际业务中的使用场景。

### string

这是最简单的类型，可以存文本、数字、甚至是序列化后的 JSON。可以用于对象缓存，比如说部分高频读取的相关业务数据我们不一定每次都要从pg等关系型数据库里查询，我们完全可以把这部分高频数据放在redis中，这样读取的时候直接GET，性能极高。

还可以用于实现计数器，比如浏览量、点赞数、下载量等，都可以用redis，Redis 的 `INCR` 是单线程原子操作，天然防并发（就是我们在点赞和配额限制里用到的）。

然后是分布式锁，处理订单时，防止多个请求同时修改同一个订单。`NX` 表示只有 Key 不存在时才设置成功。 **用法**：`SET lock:order:{orderId} "1" NX EX 10`

## hash

这是一个小型的json对象拆开存，特别适合只更新对象部分字段的场景，比如说用户要频繁修改购物车数量，用string需要把整个json反序列化再序列化，用hash只需要`HINCRBY cart:{userId} model:{modelId} 1`，直接改一个字段，极其高效且省内存。

用户快照也可以处理，把整个对象序列化成 String 更灵活，你可以单独读取或更新其中某一个字段。

## set

Set集合天然适合去重。这个就很适合点赞去重了，天然保证一个用户对同一个业务只能点一次赞。用 `SISMEMBER` 可以毫秒级判断“我是否点过赞”。还可以用于求交集，比如说都关注的对象，这个也是常见的业务场景。还有抽奖、随机推荐，SRANDMEMBER model:pool 5 可以实现从集合里随机抽取5个给用户。

## list

redis的list底层是双向链表，适合先进先出也就是fifo队列，或者最近动态。比如有人评论你的发布，那么可以使用 `LPUSH user:notifications:{userId} "{...}"` + `LTRIM user:notifications:{userId} 0 99` 把消息LPUSH到左边，然后用LTRIM只保留最新100条，不需要查询数据库，就可以直接显示。

这个也可以实现简单的消息队列，当然我们还是最好在rabbitmq里实现，毕竟术业有专攻。

## 高阶数据类型

### 位图bitmap

这个本质上是一个字符串，但是redis允许你把它当做bit数组来操作，每一位只能存0/1。1亿个用户，每个人用1bit来表示状态，总共只要12.5MB，如果用传统数据库，则可能是几个GB。这个非常适合统计每日签到/活跃打卡、连续活跃统计。
